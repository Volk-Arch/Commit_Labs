# Двухточечный интеграл: средние счёты при любом N без графа

10 октября. Собрано по условию пересмотра из `sigma-doc.md`, которое
требовало знать, где показатель числа вкладывающих пар подходит к 1.5.
Замер матрицей при `N ~ 10⁵` невозможен (10¹⁰ элементов). Оказалось,
что матрица не нужна вообще.

## Устройство

Среднее число пар с ровно `m` промежуточными элементами есть точное
двухточечное выражение

    ⟨N_m⟩ = ρ² ∫∫_{x≺y} e^{−λ} λ^m/m! d⁴x d⁴y,    λ = ρ V(x,y)

В алмазе с `T` = 1 объём интервала равен `V_T τ⁴`, где `τ` —
собственное время пары, значит

    **λ = N τ⁴ ровно**

То есть `N` входит ОДНИМ числом. Один набор пар даёт `⟨N_m⟩` для всех
`N` сразу — от 10² до 10⁹, без сприклинга, без графа, без матрицы.
Оценщик по `M` парам из `U(D)×U(D)`, ориентированным по времени:

    ⟨N_m⟩ = (N²/2) · (1/M) Σ_{связанные} e^{−λ} λ^m/m!

Множитель `1/2` — потому что ориентирование считает и `x≺y`, и `y≺x`.

## Аналитическая асимптотика (и тождество весов)

Мера пар по собственному времени ведёт себя как `q(τ) → a·τ` при
малых `τ` (объём припоясного слоя у светового конуса растёт как `τ²`).
Подстановка `u = N^{1/4} τ` даёт замкнутый ответ:

    ⟨N_m⟩ → (a/8) · Γ(m+½)/m! · N^{3/2}

Показатель **ровно 3/2**, а смесь стремится к точным отношениям

| | `N₀` | `N₁` | `N₂` | `N₃` |
|---|---|---|---|---|
| `Γ(m+½)/m!` | 1.772454 | 0.886227 | 0.664670 | 0.553892 |
| отношение | 1 | **1/2** | **3/8** | **5/16** |
| замер интеграла при `N` = 10⁹ | 1 | 0.5020 | 0.3785 | 0.3161 |

И главное — веса Бенинказы–Доукера обязаны гасить ведущий член:

    Σ_m w_m Γ(m+½)/m! = √π · (−1 + 9/2 − 6 + 5/2) = 0

**точно**. Численно `−1.8e−15`. Это и есть устройство действия БД:
ведущий член `N^{3/2}` для плоского пространства уничтожается
тождеством весов, и остаётся кривизна. Отсюда прямое объяснение, почему
`⟨S⟩` в замерах болтается около нуля без роста (50, 102, 192, 249, 156
при `N` от 100 до 1600; 878 при `N` = 10⁴).

## Постоянная меры

`a` берётся как ПРЕДЕЛ `q(τ)/τ` при `τ → 0`, а не как среднее по окну:

| окно | степень | `a` | χ²/d.o.f. |
|---|---|---|---|
| `τ` < 0.05 | 1 | 4.1242 | 0.58 |
| `τ` < 0.10 | 2 | **4.1365** | 0.87 |
| `τ` < 0.20 | 2 | 4.3042 | 3.91 |
| `τ` < 0.20 | 3 | 4.1587 | 1.03 |

Принято `a` = 4.1365 по окну с хорошим χ². Отсюда
`A_m` = 0.9165, 0.4582, 0.3437, 0.2864 и асимптотики

    P → 2.0048 N^{1.5},   Q = Σ w_m² ⟨N_m⟩ → 144.34 N^{1.5},
    σ_шум → 19.62 N^{0.75}

## Поймано при сборке

**Ошибка 1: подгонка `a` по окну, где закон уже загнулся.** Первая
версия брала взвешенное среднее `q/τ` по окну до `τ` = 0.3, где
значения идут 4.15, 4.04, 3.98, 4.02, 3.86, 3.83, 3.66, 3.43, 3.08,
2.58, 1.91, 1.17. Среднее село на большие `τ` (там больше счёта) и
дало `a` = 1.21 — мимо в **3.4 раза**. И я напечатал «плоско, закон
подтверждён» при наклоне −0.31, то есть соврал против собственных
данных в той же строке, где их вывел. Поймано контролем E.

**Ошибка 2: лишний множитель 2** в печати доли связанных (замер был
верен, печать нет).

| | |
|---|---|
| **A. Доля связанных** (Майрхейм–Майер, `d` = 4) | 0.10006 ± 0.00004 против точного 0.1 — **1.4 σ** |
| **B. Тождество весов** | `Σ w_m Γ(m+½)/m!` = −1.8e−15; отношения ровно 1 : 1/2 : 3/8 : 5/16 |
| **C. float32 против float64** | доли `τ` в полосах [0.3,0.5], [0.03,0.05], [0.01,0.02] расходятся на 0.6 %, 0.7 %, 0.2 % — счёт ведётся в float64 и в устойчивой форме `(dt−dr)(dt+dr)`, потому что при `τ` ~ 10⁻² во float32 остаётся три знака |
| **D. Интеграл против сприклинга** | 20 клеток (`N₀…N₃` при `N` = 200…3200): отношения **0.97…1.01** |

## Предсказание, проверенное прямым замером при N = 10⁴

Прямой замер при `N` = 10⁴ собран отдельно (`bigaction.py`) битовыми
множествами: матрица отношений там 10⁸ элементов, а упакованная по
битам 12.5 МБ, и `|I(x,y)| = popcount(будущее(x) & прошлое(y))` без
единого матричного умножения. 5 071 425 связанных пар, 14 с на засев.

Числа интеграла получены **до** замера:

| | `N₀` | `N₁` | `N₂` | `N₃` |
|---|---|---|---|---|
| предсказано интегралом | 724669 | 308287 | 210808 | 164061 |
| замерено (16 засевов) | 724326 | 309140 | 211480 | 164536 |
| отношение | **1.000** | **1.003** | **1.003** | **1.003** |

Битовый код сверен со старым при `N` = 3200: 0.999, 0.994, 0.997,
0.997.

Разброс при `N` = 10⁴: `σ(S)` = 20097 против предсказанных 17796, то
есть `c` = 1.294 ± 0.236 против 1.146 ± 0.028 на 200…3200 — согласно,
но слабо (16 засевов дают 24 % ошибки). Местный показатель `σ` на
шаге 3200 → 10⁴ вышел 0.9689 ± 0.24 и **не различает** предсказанные
0.846 и слоистую единицу. Для различения нужно ~85 засевов на точку.

## Где показатель подходит к 1.5

Это и был вопрос, ради которого машина собиралась. Ответ оказался
**много медленнее** моей линейной экстраполяции (я написал «≈ 10⁵»):

| показатель `P` опускается до | при `N` ~ |
|---|---|
| 1.60 | 3.2 · 10⁴ |
| 1.55 | 1.8 · 10⁵ |
| 1.52 | 3.2 · 10⁶ |
| 1.51 | 5.6 · 10⁷ |

При `N` = 10⁵ показатель `P` ещё 1.551, а `Q` — 1.569.

## Чем это полезно дальше

Любая величина, собранная из `⟨N_m⟩`, теперь считается при ЛЮБОМ `N`
без графа и с точностью 0.3 %, проверенной прямым замером. Это закрывает
нужду в сприклинге для всех средних, построенных на счётах интервалов —
остаются только флуктуации, для которых сприклинг по-прежнему нужен.

Побочно: `bigaction.py` поднимает прямой замер действия с `N` = 3200
до `N` = 10⁴ (битовые множества, 14 с на засев) — впятеро дальше, чем
матричный код.
